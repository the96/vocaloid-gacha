# ボカロ曲ガチャ

初音ミク Wiki の「殿堂入り」タグを参考にした、ボカロ曲のランダム表示アプリです。1曲または重複のない10曲を抽選できます。直前に表示した最後の曲は次の抽選から除外します（ブラウザ内に最後の曲だけ記憶）。

## GitHub Pages への公開

ビルドは不要です。GitHub リポジトリの **Settings → Pages → Build and deployment** で **Deploy from a branch** を選び、`main` ブランチの `/ (root)` を指定してください。プロジェクト Pages のサブパスでも動くよう、CSS・JS・JSON は相対 URL で読み込みます。private リポジトリからの Pages 公開の可否は GitHub プランと設定に依存します。Pages を公開するとサイトと JSON は閲覧可能になります。

手元では `python -m http.server 8000` を起動し、`http://localhost:8000/` を開きます。`file://` からは JSON の `fetch` が制限されることがあります。

## データの更新

アプリが参照するのは [data/songs.json](data/songs.json) だけです。ブラウザから Wiki へのアクセスはしません。現在の JSON は **2026-09-29 時点の小規模な初期セット**であり、Wiki の全件ではありません。更新日時は JSON の `updatedAt` に入ります。

Python 3 の標準ライブラリだけで更新できます。Wiki へのアクセスが可能な環境で、リポジトリ直下から実行してください。

```sh
python scripts/update_songs.py --pages 2
npm run lint
npm test
npm run build
git add data/songs.json
git commit -m "Update song data"
git push
```

タグ一覧は1ページあたり最大50件です。`--pages 2` は最初の2ページを対象とし、各曲ページから作曲者と動画埋め込みを確認します。範囲を広げる場合は `--pages 5` のように変更できます（全ページの収集は多数のアクセスになるため、段階的に行ってください）。既存の手動確認済みデータは保持します。各リクエスト間には既定で1秒の間隔を置きます。HTML 構造が変わって抽出できなくなった場合、スクリプトは既存 JSON を上書きせず失敗します。作曲者が取得できない場合は `null`、原曲の埋め込みが特定できない場合も `null` とします。動画リンクは埋め込みの最初の1件を推定するため、更新差分を確認してカバー動画などが混じっていないか確認してください。

依存パッケージのインストールは不要です。Node.js は検証コマンドにのみ使い、ブラウザの実行や Pages の公開には不要です。`npm run build` は静的ファイルと JSON の整合性を検査するだけで、生成物は作りません。
