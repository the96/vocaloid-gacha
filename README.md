# ボカロ曲ガチャ

初音ミク Wiki の「殿堂入り」タグを参考にした、ボカロ曲のランダム表示アプリです。リリース年の範囲とニコニコ動画の再生到達段階で絞り込み、1曲または重複のない10曲を抽選できます。開始年・終了年は片方だけでも指定でき、未指定側には下限・上限を設けません。直前に表示した最後の曲は次の抽選から除外します（ブラウザ内に最後の曲だけ記憶）。

## GitHub Pages への公開

ビルドは不要です。GitHub リポジトリの **Settings → Pages → Build and deployment** で **Deploy from a branch** を選び、`main` ブランチの `/ (root)` を指定してください。プロジェクト Pages のサブパスでも動くよう、CSS・JS・JSON は相対 URL で読み込みます。private リポジトリからの Pages 公開の可否は GitHub プランと設定に依存します。Pages を公開するとサイトと JSON は閲覧可能になります。

手元では `python -m http.server 8000` を起動し、`http://localhost:8000/` を開きます。`file://` からは JSON の `fetch` が制限されることがあります。

## 演出

1曲・10連ともページ再読み込みなしで、レコード登場 → 加速回転と音符 → 短いホワイトアウト → 左にレコードを置いた楽曲カード → 結果一覧、の順に表示します。10連のカードは1枚ずつ披露します。演出中の再抽選は無効です。スキップボタンまたは Escape で、確定済みの全結果へ移動できます。

`prefers-reduced-motion: reduce` では回転・移動・ホワイトアウトをなくし、カードを順に表示します。演出中に設定を有効にした場合は結果に移動します。レコードと音符は CSS / 文字だけで描画し、外部画像・音源は使いません。

カードは確認済みのニコニコ再生数に応じて、10万以上＝通常、50万以上＝SR（きらきら）、100万以上＝SSR（にじいろ）、500万以上＝SSR+（にじいろ＋）になります。1000万以上はSSR+のまま「神話入り」としてフィルタできます。500万以上は115曲（全体の1.56%）、1000万以上は28曲（0.38%）です。

## データの更新

アプリが読み込むデータは [data/songs.json](data/songs.json) だけです。閲覧時に Wiki にアクセスせず、歌詞・記事本文・画像・音声を保存しません。収集時の HTML はメモリ内で処理し、チェックポイントには抽出したメタデータだけを保存します。

Python 3 の標準ライブラリだけで実行できます。サイトに通常アクセスできる環境で、リポジトリ直下から実行してください。

```sh
# 既定で1～148ページ。リクエスト間隔は最低1.5秒（再試行はバックオフ）。
python scripts/update_songs.py --pages 148 --delay 1.5 --video-delay 0.5
# 中断した場合は同じコマンドで再開。成功済みの一覧・詳細は再取得しません。
python scripts/update_songs.py --pages 148 --delay 1.5 --video-delay 0.5
npm run lint
npm test
npm run build
# 全148ページと全詳細の取得を必須にする追加ゲート。
npm run data:verify
git add data/songs.json data/collection-report.json
git commit -m "Update song data"
git push
```

- `--cache` は既定で `.cache/song-metadata.json`（git 管理外）。中断しても成功した各リクエストの直後に原子的に保存します。新規に全件更新する場合は別の `--cache` パスを使います。同じキャッシュは同じ収集作業の再開用であり、定期更新には使い回さないでください。
- `--index-only` では148ページの曲名・URLだけを先に収集できます。その後、このオプションを外した同じコマンドで詳細収集を再開します。
- `--video-delay` は確認済みニコニコ原曲を動画情報APIで照会する間隔です。再生数と投稿日だけを保存し、サムネイルや動画データは保存しません。
- 欠けた一覧ページ、同一一覧の繰り返し、ページをまたぐ同一 Wiki URL を検出すると公開用 JSON を上書きしません。作曲者・原曲が不明な場合は `null` を保存します。過去データからの作曲者・動画の推測補完はしません。
- タイムアウト・一時的な5xxは最大3回まで再試行します。401 / 403 / 429 や検証画面は即停止し、チェックポイントを保持します。既存の公開用 JSON は維持します。詳細の個別失敗はレポートへ記録し、次回再試行します。
- 詳細取得エラーは作曲者未確認とは別に集計します。全一覧が取れても詳細に未取得があれば終了コード2です。作曲者表記の矛盾、同名異曲の候補、動画候補とカバー表記をレポートに記録します。同名という理由だけで別 Wiki ページを統合しません。
- 抽出器は記事コンテナ先頭の作曲クレジットを使います。候補が複数なら未確認とします。実 HTML から歌詞・本文を除いた最小限の構造をテストに反映しており、一覧の先頭・中間・末尾、通常曲、合作、カバー併記曲を照合済みです。

動画は記事コンテナ内の**クレジット直前にある主動画枠**だけを原曲投稿として採用します。曲紹介以降の関連動画、カバー文脈、主動画枠が確認できないリンクは原曲に昇格せず、候補 URL と判定理由をレポート・キャッシュへ残します。原曲・作曲者を個別に確認できた場合は `--overrides reviewed-songs.json` で以下の形式の確認記録を読み込めます。確認記録には曲ページ URL・確認日・根拠を必須とします。例中の URL・名前は説明用です。

```json
{
  "https://w.atwiki.jp/hmiku/pages/123.html": {
    "composer": "確認した作曲者名",
    "originalUrl": "https://www.nicovideo.jp/watch/sm123456",
    "checkedAt": "2026-09-30",
    "reason": "Wikiの原曲表示と投稿者・動画タイトルを照合"
  }
}
```

`npm run build` は静的ファイルと JSON の整合性検査です。全件収集の成功判定は `npm run data:verify` で分離しています。依存パッケージのインストールやバンドルは不要です。

## 検証

`npm test` は、重複防止・年範囲/再生数フィルタ（片側未指定を含む）・演出順・スキップ後の古いタイマー無効化・連打防止・reduced motion、および収集再開・欠損時の既存JSON保護・重複検出・作曲者の矛盾・カバー動画の誤採用防止・動画情報APIの解析を検証します。

2026-09-30 にローカル HTTP と実ブラウザで、年/再生数フィルタ、1曲・10連の全演出、spin / flash / reveal 各段階のスキップ、Escape、再抽選、古いタイマーの無効化、10連内の重複なし、SSR+表示、390px幅の横あふれなしを確認しました。実行時通信は同一オリジンの静的ファイルと `data/songs.json` だけです。`prefers-reduced-motion` は CSS とシーケンスの自動テストで検証していますが、今回のブラウザ環境では OS 設定のエミュレーションは未確認です。
